# Source handling

## Operator source policy and current official context (2026-10-12)

SEC visitor requests and scheduled ingestion are disabled by operator instruction, even if a legacy contact identity exists. The old visitor route returns HTTP 410 with code disabled without upstream access. Older sweep callers receive not-searched, not an empty successful sample. No SEC contact email is required. Earlier audit entries describing missing SEC setup are historical observations, not current instructions.

Explicit currency/FX searches can use the ECB's [official daily XML snapshot](https://www.ecb.europa.eu/stats/eurofxref/eurofxref-daily.xml). The [ECB reference-rate page](https://www.ecb.europa.eu/stats/policy_and_exchange_rates/euro_reference_exchange_rates/html/index.en.html) describes working-day publication and discourages transaction use; its [free-use conditions](https://www.ecb.europa.eu/services/using-our-site/disclaimer/html/index.en.html) require accurate reproduction and attribution, with modification disclosures when applicable. Atlas displays unmodified USD and selected-currency units per euro, without computing cross-rates or returns. Euro-area lenses share EUR; no separate country quote is invented. Future/impossible dates and invalid rates are rejected, duplicate currencies withheld, missing currencies and dates older than seven calendar days marked partial. Weekends/holidays are not mistaken for a guaranteed failure. Observation date and original provider-fetch time remain separate.

The feed has a fixed host/path, six-second bounded read and 100 KB body cap, no query-text transmission, a fifteen-minute coalesced warm-instance cache across lenses and one-minute failure backoff. This is best-effort per instance, not distributed traffic coordination. XML entity declarations are rejected. Rates remain official statistical context, excluded from every opinion summary. The [simulated reviewer panel](simulated-review.md) is AI-authored design feedback, not independent empirical acceptance.

## Bluesky declared creation time, not index time (2026-10-12)

The freshness gate no longer falls back to AppView `indexedAt` when record `createdAt` is absent. The [post schema](https://raw.githubusercontent.com/bluesky-social/atproto/main/lexicons/app/bsky/feed/post.json) defines creation time as client-declared, while the separate [post-view schema](https://raw.githubusercontent.com/bluesky-social/atproto/main/lexicons/app/bsky/feed/defs.json) carries indexing metadata. Newly indexed old/undated material must not be labeled newly published. Atlas requires an explicit timezone and seconds, a real Gregorian date, valid time/offset fields, and a declared instant within the seven-day window and no later than retrieval start. Missing, malformed, stale or future declarations are excluded, not repaired using indexing time. Search still considers only the latest bounded 25 API returns, not an exhaustive seven-day corpus. The displayed date is explicitly client-declared and unverified; it cannot establish an underlying event date or actual publication truth.

Following the [Lexicon datetime rules](https://atproto.com/specs/lexicon#datetime), the adapter accepts uppercase T/Z, explicit offsets except negative zero, and fractional seconds including microseconds. Comparison/display reduces fractions to millisecond resolution and caps input length at 128 characters. This is an operational parser for modern posts, not a full historical/arbitrary-length Lexicon validator; older dates are outside the search window. No source, query count or text-copy allowance is added.

## Excerpt boundaries and missing context

Discussion previews and model excerpts now clip at whole word segments rather than arbitrary string positions. Numeric-bearing whitespace tokens receive an additional whole-token guard because segmenters may separate scientific notation, date punctuation or signed values. This prevents a boundary cut from exposing only the leading digits of a different figure. Short original text is unchanged; long single words that cannot fit are withheld. Bluesky/model excerpts remain capped at 300 UTF-16 units, and Mastodon/Lemmy discussion previews at 1,200. Title clipping in the Lemmy adapter uses the same boundary protection. No copied-text budget or upstream request count was increased.

The implementation uses the standard [ECMAScript word segmenter](https://tc39.es/ecma402/#segmenter-objects); language-specific segmentation can vary by runtime. Older runtimes without that facility withhold overlong text rather than fall back to unsafe partial-word cuts. CJK can be segmented without whitespace, but a long whitespace-free span containing digits may be conservatively omitted if it crosses the boundary. This is not sentence completeness or semantic context preservation: a scale/unit in a later word, negation in the omitted suffix, or a qualification in another post can still change interpretation. A surviving short figure is not automatically a complete financial quantity. Original links, excerpt-only warnings and independent human review remain necessary. Synthetic boundary tests are not fluent-language or factual-summary acceptance.

## Conservative copy detection

Statistical dataset pages may contain several currencies, series or dates. Display deduplication and repeated-view URL flags therefore use operator-scoped observation IDs for official statistical records, not the shared dataset-page URL. The same observation returned in another view still collapses; different observations remain visible. Discussion URL/text deduplication is unchanged, and statistical records remain outside opinion synthesis. Stable adapter observation IDs are required; this is not proof that distinct rows or data providers are independent corroboration.

Long-text near-copy detection requires at least 90% shared five-token shingles in **both** texts (four-character shingles for CJK), with at least eight shingles in the smaller text. Containment alone is insufficient: a post containing another paragraph can add substantial different experience. Literal numeric support is checked in both directions before treating texts as near copies, preserving changed figures, common currencies, scales and recognized percent/basis-point units. Small paraphrases may now remain separate rather than being prematurely suppressed. Exact URL/text collapse and per-author selection caps remain separate controls.

The two comparison groups share selected long-text copy exclusions: a near-copy already selected for the baseline cannot become another perspective in the selected lens. The first selection keeps the citation; this deterministic baseline-first choice is not a judgment of originating authorship or geographic relevance. Only selected records seed cross-group exclusions, not every fetched candidate. Before any AI quota/provider call, the server separately rejects retained within-group or cross-group exact long copies and conservative near-copies even when they carry different citation IDs. Short generic matching wording from distinct source labels is not enough to reject a request. Client-supplied source labels and excerpts remain unverified at this boundary; these checks are not cryptographic provider provenance, identity resolution, or protection against fabricated unique material.

These are conservative lexical heuristics, not semantic independence validation. They do not establish that matching quantities refer to the same metric, protect every multilingual unit, or detect a short negation that reverses an otherwise matching passage. Summary selection compares redacted excerpts capped at 300 characters; differences beyond that window cannot inform this heuristic. Displayed source links remain available for original-context inspection. Empirical duplicate precision/recall and counter-evidence retention still require independently labeled examples; synthetic tests do not establish those acceptance rates.

Production ingestion stores records returned by individually enabled source connectors. Available metadata may include source name/domain, URL, publication time, market/language labels, title, and connector metadata. Metadata completeness depends on the source; source-specific content is filtered according to its reviewed retention and attribution rules.

The scheduled Stack Exchange feed samples the newest public questions from 12 English-, Spanish-, Portuguese-, Japanese-, and Russian-language communities spanning economics, quantitative finance, personal finance, politics, law, AI, data science, security, and programming. It makes at most one request per community per daily run, asks for at most 100 records per community in a rolling 30-day window, and retains only individually CC BY-SA 4.0-licensed titles, tags, dates, canonical links, and author attribution; scheduled question and answer bodies are not retained. This is a broad current expert-Q&A feed, not general-purpose public opinion or a representative forum sample; all 12 communities are still one platform operator. API quotas, page limits, source activity, license exclusions, and backoff can reduce coverage. On-demand Stack Exchange search may now return at most one recent, individually CC BY-SA 4.0-licensed answer excerpt per matched question; it is shortened for display, transient, attributed to its author and source, and excluded from AI summaries. Other on-demand source connectors retain citation metadata and discard post bodies as described in their source-specific policies. GDELT scheduled ingestion is disabled after repeated HTTP 429 responses; optional visitor searches use a first-party no-store bridge and may still be throttled. Bluesky is available only for transient, citation-only visitor searches; scheduled ingestion and persistence of post text are disabled. No Korean general-forum connector is active.

The currently enabled licensed analysis/reporting feeds include The Conversation's English editions and Global Voices' English, Spanish, French, Portuguese, Arabic, Russian, Italian, Dutch, Yoruba, Ukrainian, Greek, and Catalan editions, alongside separately labeled European Commission official context. These publication feeds are not general forum conversation. Global Voices entries are limited to a seven-day rolling publication window. Individual rights checks and source attribution govern storage; story bodies/summaries are discarded where the connector requires title-only retention. Localized Global Voices editions may carry translations; cross-source review displays feed-provided publisher labels separately from edition names, but neither labels nor multiple editions establish corporate independence.

On-demand BIS effective-exchange-rate context is a separate, keyless statistical lookup triggered only by explicit currency/FX terms. It requests the latest bounded monthly nominal and real broad-basket indices for the U.S. and selected country, identifies any missing or stale series, and links to the BIS series. Topic text is not sent to BIS. The provider's stated terms permit statistical use with attribution and non-misleading presentation. Indices use separate 2020=100 bases, are not bilateral spot rates, and are not compared by level; they are excluded from community discussion and AI-summary evidence.

Lead review's discussion–reporting overlap is computed transiently from eligible Stack Exchange questions, Fedora Discussion topic metadata, and licensed analysis/reporting rows in the preceding seven days. Phrases may be individually CC BY-SA 4.0 Stack Exchange community tags or exact two-to-four-word excerpts from Fedora topic titles. Tags are applied by the source community; Fedora excerpts are generated from titles and are not platform-applied tags. Ambiguous acronym-only phrases and excerpts containing listed English function words are suppressed to reduce generic collisions; this heuristic can omit relevant phrases. Typst Forum topics are not currently included in this overlap view. Matching uses whole token boundaries and does not merge translations or paraphrases. The view returns linked original titles/dates/source labels and caps evidence links per phrase. It is lexical discovery—not proof of shared event, influence, source independence, sentiment, financial materiality, or a lead. No extra content is stored by this calculation.

Wikinews is excluded from live research: the Wikimedia Foundation closed its editions effective 2026-05-04, leaving read-only archives. A live English API search returned only 2024 material, so archive items are not presented as current evidence.

Do not infer source quality, permission to republish, or population representativeness solely from successful retrieval. Preserve attribution and links, minimize copied text, respect source terms and rate limits, and disable a source if the intended use is not permitted.
## PyTorch bounded first-post sample (2026-10-12)

Atlas's explicit GPU/inference/framework searches also inspect PyTorch Forums' public latest-topic feed. This adds one technical community operator, not general investing discussion or another national sample. One feed read considers only the first 30 active public topics; exact normalized title words screen candidates locally. At most three candidate topic JSON pages are read, sequentially, and only original posts created within 30 days are retained. Replies, older bumped first posts, historical search, pagination and the robots-disallowed `/search` endpoint are not used. No result in this narrow feed cannot establish topic absence. Queries without an explicit supported technical term do not call this source.

The [forum terms](https://discuss.pytorch.org/tos) link to [LF Projects terms](https://lfprojects.org/policies/terms-of-use/), which provide a general CC BY 4.0 content license with exceptions for project contributions, separately licensed and third-party content. This is a scoped reuse basis for ordinary prose, not a blanket legal guarantee or artifact/code license. Atlas removes code, quotations, link labels/previews, media, scripts and styles, and conservatively excludes visible rights notices. Attribution, original topic link, actual first-post date, license link and a shortening/format-removal notice accompany retained excerpts. Operator review and takedown obligations remain; automated HTML stripping cannot prove original authorship or clear every third-party right. No forum account, credentials, payment or signup is required.

Feed/topic failures are distinguished from empty matching samples; failures and matching-topic truncation set partial status. Counts explicitly report feed size, title matches, reads, failures and prose/safety exclusions. The server coalesces provider pages across queries for 15 minutes and reports the oldest contributing provider-fetch timestamp. Cache/limits are volatile, best-effort per warm instance (three visitor queries/minute, ten new provider reads/minute), not globally coordinated infrastructure. Free upstream access, future terms and source moderation can change. The complete adapter has a seven-second deadline and bounded page sizes. Non-OK responses back off for one minute.

Language is not reported, contributor location is unknown, and technical self-reports may be promotional or inaccurate. These excerpts are excluded from AI summaries until their handling is validated; they are available as auditable research context only. One new operator and a three-record live smoke test do not satisfy coverage, relevance or research-quality acceptance gates.
