## 2026-10-11 continuation

The summarizer response contract now returns each overview/comparison as 1–4 discrete claims, each with its own exact citation IDs. The server rejects the complete AI response if any claim is uncited, cites an ID outside the request, or uses a source from the opposite lens for a side-specific statement. This is structural citation validation only; Atlas cannot automatically determine whether a cited excerpt semantically entails the claim. The search UI keeps citation IDs out of the overview and presents them together with the source records below it. Commit `bc68721` implements claim-level validation; `35f8d27` removes inline citation markers.

Verification after these changes: 387 tests across 62 files pass; TypeScript check and optimized production build pass. The production URL verifier returned 25/25 checks, including all public routes, fail-closed protected endpoints, and live keyless Crossref/arXiv/OpenAlex metadata routes. It does not make a live AI request, so it does not verify Groq availability, latest deployment revision, summary truthfulness, topic relevance, or research-quality acceptance. Do not interpret a successful empty result set or a passing endpoint check as evidence of topic absence or source representativeness.

Follow-up hardening: claim validation now rejects multiple sentences inside a single cited claim, requires each cross-lens comparison claim to cite at least one item from each side, and discards model-generated limitations because they were uncited free text. Existing deterministic product caveats remain visible. Focused tests pass (35), and the full suite passes (390 tests across 62 files); TypeScript check and optimized build pass.
